# Тесты mini-app прототипов

Замеры, на которых основаны выводы в `docs/`. Запускать из этой папки. Один тяжёлый прогон за раз, ноут на 8 ГБ.

## Подготовка (один раз)
```bash
cd ~/Claude\ Code/miniapps/tests && npm i      # playwright-core, браузер берётся из кэша ~/Library/Caches/ms-playwright
```

## Нячанг Дом v2 (с сервером)
```bash
node nhatrang.mjs                       # 276 проверок, около 100 секунд, отчёт ../docs/nhatrang-report.json
node stress.mjs nhatrang 40 60 8 3      # 40 ботов, поднимает свой тестовый сервер на :8792
```
Тесты сами поднимают `nhatrang/server/tools/test_server.py` (свежая БД во временной папке, сид-данные, поддельный бот, порты 8790 и 8792) и гасят его по PID. Нужен `nhatrang/server/.venv` (`cd nhatrang/server && UV_PROJECT_ENVIRONMENT=.venv uv sync --python 3.12`). Leaflet грузится с cdnjs: без сети тест флажков и карты упадёт. Запускать по одному. Серверные тесты: `cd nhatrang/server && UV_PROJECT_ENVIRONMENT=.venv uv run --python 3.12 pytest -q`.

Старые `e2e.mjs`, `telegram-real.mjs`, `shots.mjs` теперь для `reels-radar` и `faceless` (прототип nhatrang в них убран). `telegram-real.mjs` для nhatrang не гоняется: ветку «настоящий Telegram» (initData, openInvoice) проверяет `nhatrang.mjs`, остальное (BackButton, safe-area) лежит в общем `shared/tgx.js` и покрыто на других приложениях.

## Сквозные проверки (e2e) для reels-radar и faceless
```bash
node e2e.mjs && node summarize.mjs
```
Что делает: каждый экран каждого приложения на ширинах 360/390/430 в светлой и тёмной теме (один активный экран, не пустой, нет горизонтального скролла, тап-зоны не меньше 36 px, контраст текста WCAG AA), затем сценарии по кнопкам и переходам. Отчёт: `../docs/e2e-report.json`. Идёт около 12 минут, потому что это 540+ проверок раскладки.

## Проверка «как в настоящем Telegram»
```bash
node telegram-real.mjs [app]      # около 5 секунд на приложение, 76 проверок, отчёт ../docs/telegram-real-report.json
```
e2e и стресс гоняют мок-ветку `shared/tgx.js`. Этот тест подменяет `telegram-web-app.js` на поддельный `Telegram.WebApp` с `initData` и проверяет ветку `real`: `ready/expand/disableVerticalSwipes` по разу, тема от `colorScheme`, нет рамки и шапки-имитации, haptic при переходах, на каждом содержательном экране есть способ вернуться и нет тупиков, нативная `BackButton` следует стеку (видна на глубоком экране, нажатие возвращает, на корне скрыта), нижние элементы (табы, главная кнопка, шторка) поднимаются при `--tg-safe-area-inset-bottom` (iPhone), отказ буфера обмена не роняет страницу, старт без сети. Не проверяет: настоящую клавиатуру, реальные устройства.

## Стресс «много ботов»
```bash
node stress.mjs <app> [users=20] [actions=60] [concurrency=10] [seed=1]
# пример: node stress.mjs reels-radar 40 60 8 2
```
Каждый «бот» это изолированный контекст браузера со случайным обходом интерфейса (тапы, ввод, «назад», жёсткий ввод: XSS-строки, эмодзи, 3000 символов). После каждого действия проверяются инварианты: ровно один активный экран, нет XSS, лимит просмотров не уходит в минус, нет горизонтального скролла. Результаты: `../docs/stress/<app>-<N>u.json`, при одинаковом seed прогон воспроизводится.

Важно: это проверка интерфейса под параллельными сессиями. Бэкенда в прототипах нет, поэтому нагрузку на API и оплату этот тест не проверяет. Для боевой версии нужен отдельный тест API (k6 или locust) и тест оплаты на стороне провайдера.

Ресурсы: 8 параллельных контекстов дают пик около 1.8-2.0 ГБ RSS у Chromium. Выше 10 параллельно на этой машине не поднимать.
